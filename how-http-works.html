How HTTP Works

A browser asks for something, a server processes the request, and the server returns a structured response.

A Typical Web Request

  1. The user enters a URL or clicks a link.
  2. The browser locates the destination server and prepares a network connection.
  3. The browser sends an HTTP request with a method, target, headers, and sometimes a body.
  4. The server processes the request and chooses a result.
  5. The server sends an HTTP response with a status code, headers, and optional body.
  6. The browser uses the returned content and may make more HTTP requests for CSS, JavaScript, images, fonts, or API data.

Request and Response Anatomy

Start line

A request begins with a method and target, such as GET /products.html. A response begins with a status such as 200 OK.

Headers

Headers describe metadata such as content type, caching rules, authentication, cookies, accepted formats, and compression.

Body

The body carries the payload when needed. It might contain HTML, JSON, form data, an uploaded file, or another media type.

Status Code Families

  • 1xx — Informational: the exchange is continuing.
  • 2xx — Success: the request worked, such as 200 OK.
  • 3xx — Redirection: another location or follow-up step is required.
  • 4xx — Client error: the request cannot be fulfilled as sent, such as 404 Not Found.
  • 5xx — Server error: the server failed while handling the request, such as 500 Internal Server Error.

HTTP Is Stateless

HTTP is designed so each request can be understood on its own. Websites create continuity across requests with tools such as cookies, session identifiers, tokens, browser storage, and server-side databases.
